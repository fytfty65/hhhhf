# 四季门户：公网部署注意事项

## 范围与当前状态

本任务只修改本地前端呈现及原创素材，不执行公网部署，不修改数据库、认证协议、生产环境变量或服务器服务。素材和页面必须一起发布。实际测试结果将在本地验证完成后补充；本文件不是已上线证明。

## 与现有部署流程的关系

现有 `deploy/deploy.sh` 将源码解压到 `/opt/omniroute/srv`，在独立 `.next-build` 构建后切换 `.next`，并重启网关、AI、前端及重载 Nginx。它不是仅前端发布脚本，不应为了换登录页不加检查就执行。

现有脚本切换后立即删除 `.next-old`，因此该目录不能视为可用的长期回滚版本。正式上线前应另外保留前一版源码、生产环境配置（安全保存，禁止提交）和构建产物；回滚时恢复对应的 public 素材，不能只回滚 JS。

## 资源约定

- 网页资源从同源 `/hero/v5/` 加载，不依赖第三方 CDN，也不申请地理定位。
- 生成脚本与可编辑母场景用于本地制作。不要把 Blender 程序、下载压缩包、渲染中间 PNG、测试截图或整个 work 目录放进生产包。
- 生产仅需要完成压缩的 WebP 随 `front/public` 部署。
- 版本目录如果重新覆盖同名图片，不应配置一年 immutable 缓存。下一次资产更新优先更换版本目录。
- Next.js 构建时读取 NEXT_PUBLIC 环境配置。不得用本地 API 地址覆盖服务器现有 `.env.local`。

## 上线前检查

1. 在本地执行 typecheck、lint、Node 测试、生产构建及登录页 E2E。
2. 人工检查四季桌面和手机画面、注册和两阶段重置密码，确认无横向溢出和不可见按钮。
3. 确认服务器可承载既有构建流程；原脚本对小内存主机使用 cgroup 资源上限，应保留。
4. 明确部署目标、发布窗口和回滚备份后再由负责人执行部署。
5. 发布后通过实际公网地址确认 `/hero/v5/` 资源返回正确的图片类型、无 404；无痕窗口检查登录页，已登录窗口检查仍直接进入大厅。
6. 验证 HTTPS、反向代理和 Cookie 行为不变；本地 mock E2E 不替代真实认证回归。

## 回退

恢复上一份前端源码、对应 public 素材和构建产物，使用原生产环境配置重启前端。不要触碰认证数据库或为了背景回退重置用户账号。资源失败时页面仍应保留可用表单和当前成功加载的场景；这只是故障兜底，不能代替发布回滚。
