# 供应商可用性与无商业资质运行策略

平台不把途牛或任何商业供应商作为规划前置条件。没有凭据时，供应商保持 `not_configured`，规划继续使用高德候选池、已有只读适配器和透明估算降级；系统不会猜测价格、余票、库存或订单状态。

## 当前运行模式

| 能力 | 可用来源 | 没有来源时的行为 |
| --- | --- | --- |
| POI、景点、餐饮、地图核验 | 高德（`AMAP_API_KEY`） | 保留候选池或公开核验链接，并标记数据时效 |
| MCP 只读查询 | RollingGo（配置 endpoint、token 和 `*_PROVIDER_PROTOCOL=mcp`） | 使用统一 fallback，不调用 mutation 工具 |
| 住宿/交通价格与库存 | 仅在已授权的只读供应商 schema 通过审计时使用 | 标记“暂无可核实数据”，提供高德、12306、Trip.com 官方入口 |
| 途牛下单/取消 | 当前不启用 | 不发起请求，不影响路线规划 |
| Trip.com | 无 API 时仅作为官方导流 | 不抓取、不伪造实时价格或预订状态 |

## 安全边界

1. `tools/list` 必须先通过脱敏 schema 审计；字段名、类型、枚举和必填规则任一不匹配，工具保持禁用。
2. 查询工具与下单/取消工具分离。规划、天气、客流链路永远不会调用 mutation 工具。
3. 订单接口需要用户确认、`trip_id`、幂等键、身份授权和明确订单字段；没有供应商凭据时返回可解释的 `PROVIDER_NOT_CONFIGURED`。
4. 官方链接是核验入口，不代表平台已报价、已出票或已预订。
5. 多来源冲突会写入脱敏质量指标 `source_conflict_count`，只记录数量和字段名，不保存供应商原始响应。

## 建议的联调顺序

1. 先使用本地脱敏 fixture 验证 RollingGo 的 `tools/list` 和字段映射。
2. 再在供应商提供的 staging/sandbox 环境进行只读 smoke test。
3. 只有在 staging 明确支持且经过用户确认后，才单独验证下单与取消；生产环境继续保持官方渠道导流模式。
