# anchoring 尺子修正的定案验证（2026-10-08）

## 要回答的问题

上一批修了三个 anchoring 相关 bug 后，在**已有方案**上重算发现分数普遍上升：

| 方案 | 旧分 | 新分 |
| --- | --- | --- |
| kel8（库尔勒 18 节点） | 0.750 | **1.000** |
| ks20（喀什 17 节点） | 0.714 | **0.833** |
| hejing3（和静 23 节点） | 1.000 | 1.000 |
| yn24 / yn25（伊宁） | 0.714 / 0.500 | 0.714 / 0.500 |

**"重算后分数变高"本身不能证明尺子修对了** —— 也可能只是尺子变松了。
两者后果完全相反：尺子修对是好事；尺子变松是坏事（以后什么方案都能拿高分，失去分辨力）。
所以必须把两者分开。

## 怎么分

把**同一份 payload** 喂给两套"谁算吃住侧"的判定规则，其余（距离、坐标、阈值）
一律调用线上实现：

- **旧判定**：`desc`（含**地址**）也参与匹配，且单字关键词算数 —— 复刻修复前行为；
- **新判定**：只看结构化字段、关键词 ≥2 字 —— 线上 `_is_anchor_side`。

复现命令（在 `ai-service/` 下执行）：

```powershell
.\venv\Scripts\python.exe -u ..\work\verify_anchor_ruler.py          # 逐案例对照
.\venv\Scripts\python.exe -u ..\work\verify_anchor_discrimination.py # 全量 + 破坏测试
```

> ⚠️ 第一版脚本把距离与坐标读取也自己抄了一遍，结果"有坐标 0 / 全是 0.000"，
> 与线上 `score_anchoring` 对不上。**自己抄一把尺子就是"两把尺子"**，正是本项目栽过的坑。
> 现在只替换"谁算吃住侧"这一个判定。修复后与线上逐案一致（`✓ 一致`）。

## 结论：提升全部来自误判修正

逐案例的**判定翻转**（旧当吃住侧 → 新不当）恰好解释了全部分差：

| 方案 | 翻转的节点 | 旧口径下被扣的原因 | 结果 |
| --- | --- | --- | --- |
| kel8 | 博斯腾湖风景名胜区（风景名胜） | 地址「巴音郭楞焉耆盆地东南**面**博湖县境内」被单字「面」命中当饭点，判 45.2km 超距 | 吃住侧 4→3，check 4→3，3/3 = **1.000** |
| ks20 | 胡杨书院（科教文化服务） | 地址「巴楚镇新村路(巴楚博物馆后**面**)」被同一个单字「面」命中，判 224.1km | 吃住侧 7→6，check 7→6，5/6 = **0.833** |
| hejing3 | 无翻转 | — | 1.000 → 1.000 |
| yn24 / yn25 | 无翻转 | — | 分数**完全不变**（0.714 / 0.500） |

两处误判是**同一个**关键词「面」在地址里的两种写法（「东南**面**」「后**面**」）。
复现：

```powershell
.\venv\Scripts\python.exe -u ..\work\dbg_keyword_hit.py   # 打出命中的关键词及其上下文
```

关键证据：**被扣的分正好等于误判节点的分**，没有任何真实吃住节点因为"尺子变松"而免罚。
yn24 / yn25 分数一点没动，说明不是"一律加分"。

## 尺子没有变松（三条独立证据）

1. **真实违规仍然被抓**：全量 120 份方案里，新尺子仍判出 **98 个超距节点，分布在 35 份方案**里。
   例如 ks20 里「岳普湖县双福美食 71.6km」在**新旧口径下都被抓住** —— 该扣的照扣。
2. **分数分布没有塌**：满分方案 40/120（旧）→ 76/120（新）。
   上升来自误判修正；仍有 44 份方案拿不到满分，分辨力在。
3. **正向破坏测试**：给一份满分方案（final1-喀什-17）故意把「正宗福建馄饨王」挪到约 200km 外，
   分数 **1.000 → 0.800**。尺子对真实违规有反应 —— 这是"没扣分≠尺子好"的反向证据。

## 踩坑记录（两个都是"测试写错，不是尺子失灵"）

差点把测试 bug 误判成"尺子对违规无感"，两次都记下来：

1. **改错了字段**：真实 payload 的坐标只存在 `lnglat`（`lat`/`lng` 是 `None`）。
   第一版去改 `lat` 并把数组当成 `[lat, lng]`，一个字段都没动到。
2. **改了拷贝**：`nodes_of()` 默认 `copy=True` 返回**浅拷贝**（这是刻意设计：
   读/算分不应污染方案）。破坏测试必须用 `nodes_of(plan, copy=False)`，
   否则改的是拷贝、落不到 `route` 上。

两次症状都是"分数纹丝不动、看起来像尺子失灵"。**先怀疑自己的测试**再怀疑被测对象。
现在破坏测试里带了 `改动生效=True/False` 的自检，没生效就直接说"无法据此判断"，
而不是把无效实验当成结论。

## 一句话结论

kel8 0.75→1.00、ks20 0.714→0.833 是**尺子修对了**（原来扣的是误判），不是方案变好、
也不是尺子变松；同时新尺子仍然抓住 98 个真实超距节点，并对故意破坏有明确反应。
